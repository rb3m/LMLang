# ADR-026 Native builds via a Go backend; Int becomes 64-bit with checked overflow (proposed 2026-10-16, M8)

Goal (owner): agents write scripts and applications in LM that run quickly and with minimal fuss on the owner's Mac and Linux machines. Remote hosting (DreamHost) is a later concern; the owner will report which of Python, PHP or a native binary the plan can run.
Decision 1, target. Compile checked programs to Go source and build with the `go` toolchain into one static binary per entry point (`lm build MOD.FN [--target go] [--os linux|darwin] [--arch amd64|arm64]`). Why Go over Rust: LM values are immutable and freely shared, which a garbage collector matches directly (Rust would need `Rc`/clone everywhere); closures cost nothing extra; goroutine stacks grow to ~1GB, so deep recursion without tail calls (ADR-020) keeps working; sub-second compiles keep the edit-check-test loop tight; cross-compiling is an environment variable; `math/big` is in Go's standard library if ever needed. Rust's enum/match/Result map more neatly onto sum types and `fails`, but that does not outweigh ownership friction and compile time for this language. C was rejected (we would write our own GC and closures).
Decision 2, shared lowering. Backends do not read the AST directly: a lowering pass turns the checked `Program` into a small target-neutral IR (mangled names, explicit closures and captures, `match` as tag/field tests, `fail`/`try` as explicit error flow, contracts as guarded assertions). Each backend is a printer over that IR plus a runtime file implementing the prims. Why: a later Python or PHP backend for the server is then a thin printer, and all backends share one place where semantics can go wrong.
Decision 3, Int. SPEC sections 1, 11 and 13 change from unbounded Int to signed 64-bit Int; any `+ - *` (and `/` of min-int by -1) that overflows fails with a new prelude error `Overflow` instead of wrapping. The interpreter enforces the same bound, so the reference semantics and every backend agree. Why: unbounded ints are free in Python but slow in Go and awkward in PHP; silent wraparound would break the "examples are the semantics" property (ADR-019); a declared failure keeps programs total and diagnosable. Cost: `Overflow` behaves like `DivZero` (implicitly possible on arithmetic, not declared in `fails`; listed in the SPEC section 7 prelude next to DivZero). [Superseded by ADR-029/ADR-030: overflow is the runtime fault E-OVERFLOW, and DivZero is in fact declared.] Revisit if an experiment needs big numbers (then add a `Big` type, not a silent mode).
Decision 4, oracle. The tree-walking interpreter stays the reference implementation. Every `example` in stdlib, examples, tests/spec/run and bench tasks is run both interpreted and compiled, and results must be identical (printed in LM syntax). Floor division and `mod` are runtime helpers in each backend (Go and PHP truncate toward zero).
Constraints kept: the toolchain stays stdlib-only Python; it emits Go source and shells out to `go`, which is needed only on the machine that builds (the produced binaries need nothing). `lm build` reports a usage error (exit 3) if `go` is missing. The cloud sandbox has no Go today, so compiled tests skip there with a visible notice, never a silent pass.
Prerequisite: real I/O (command-line args, stdin, file read/write, exit codes) lands first, because a binary that can only `io.print` is not an application.
