# ADR-057 Float math lives in `float`, faults on bad domains, one pinned algorithm per function (backlog 13 design; 2026-10-17, agent consensus)

Context: backlog 13 (owner) asks for "fun math" on Floats: logarithms, exponentials, trigonometry, powers and roots, constants. The Roadster Lander had to sum its own logarithm series (ADR-054). `float` has from-int, rounding, sqrt, abs, min, max, sum; `math` is Int-only. Python and Go must agree bit for bit (differential tests), but platform libm results differ in the last unit in the last place (ulp), and sin/exp/pow are not correctly rounded there.

Decisions:
1. Location: grow `float` (`float.ln`, `float.sin`, `(float.pi)`); `math` stays Int-only and receives future Int functions (pow, gcd). The argument type decides the module; `float.abs` and `math.abs` are distinct qualified names, so no ADR-047 exception arises. Rejected: a Float-based `math` (migration, mixed types), a new module (another classification rule). (agy, Codex)
2. Domain errors: an invalid real domain or a non-finite result is the fault E-FLOAT, as for `float.sqrt`; finite underflow is allowed. Callers who need recovery validate inputs first. The SPEC lists edge cases explicitly (`ln 0.0`, `pow 0.0 0.0`, negative base with integral exponent, `atan2 0.0 0.0`); `cbrt -8.0` is `-2.0`, `pow -8.0 0.5` faults. Rejected: Opt or declared fails per function (inconsistent signatures). (agy, Codex)
3. Agreement: phase 1 implements one fixed, versioned reference algorithm per function in both runtimes (a port of Go's pure-Go `math` / FreeBSD msun), never platform libm or Go's arch-specific assembly. SPEC contract: deterministic, identical on every platform, error <= 1 ulp; high-precision reference vectors are evidence for the bound, not proof. `sqrt` stays correctly rounded. Constants are pinned by exact bit patterns; zero normalization, FMA and subnormals are controlled as in ADR-039. Changing any function's result bits later (for example to correctly rounded, CORE-MATH style) needs its own ADR with an explicit compatibility decision. Ship incrementally: core set first (ln, exp, log2, log10, sin, cos, tan, asin, acos, atan, atan2, pow, cbrt, hypot, pi, e), extras after.

Who agreed: agy and Codex on 1 and 2. On 3 agy proposed porting Go's algorithms and Codex proposed correctly rounded results; both accepted Claude's phased compromise, with Codex's conditions (versioned algorithm, vectors as evidence, compatibility ADR before changing bits) adopted.
