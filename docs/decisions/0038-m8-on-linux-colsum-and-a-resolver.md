# ADR-038 M8(e) on Linux: `colsum`, and a resolver pass-order fix (2026-10-16)

Wrote `examples/colsum.lm` (CSV group-and-sum CLI: `io.args`, `fs.read`, `str.split/trim/to-int/lines`, records, list patterns, `do`, `try`, Int exit status) as the M8(e) script and built it with `lm build colsum.main`. On 200,000 rows the binary matched a Python reference exactly in 0.14 s; on 20,000 rows it ran in 0.026 s against 1.55 s for `lm run`. Exit statuses: 0 ok, 2 usage, 1 I/O error. A darwin/arm64 binary cross-builds; running it on the owner's Mac is the open part of M8(e).
Bug found by writing it: `Resolver._decls` classified a type as record/sum in the same loop that resolved field types, so a field (of a type or an error) naming a record/sum declared later in canonical (alphabetical) order resolved as an alias with no body and was rejected as "malformed type", blamed on the later type. Since the printer sorts types by name, the only workaround was renaming types. Fix: classify every type first (fixture tests/spec/check/type-forward-ref.lm). Same family as the ADR-022 pass-order bug: resolver passes must not depend on declaration order. Revisit: if another order-dependence appears, resolve declarations as a graph instead of in passes.
Second bug found the same way: `Resolver._fields` numbered fields from 0, ignoring the items before them in the parent form (`rec` head, variant name, error name), so recorded reference paths for types used in record/variant/error fields pointed one or two nodes off. `rename` rewrites exactly those paths, so renaming such a type would have edited the wrong atom. `_fields` now takes the parent index of its first node; tests: `RefPathsAreAddressable` (now exercised by colsum) and `test_rename_type_used_in_fields`. Earlier examples only had Int/Str fields, so no field reference was ever recorded.
M8(e) completed on macOS the same day: on the owner's M1 Mac Mini the unit suite passes with Go, and both the binary cross-built on Linux and a native build produce identical `colsum` output. M8 is done.
