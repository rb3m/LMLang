# ADR-032 M8(b) implemented: 64-bit Int and E-OVERFLOW in the interpreter (2026-10-16)

Implements ADR-029 as amended by ADR-030; records the choices the ADRs left open. Decided by Claude under ADR-030's delegation.
1. Diagnostics gain an optional `data` object (code-specific structured fields), omitted from the JSON when empty, so every other diagnostic prints exactly as before. E-OVERFLOW puts `op`, `operands`, `bounds`, `frames`, `frames_omitted`, `user_path` and `replay` there (SPEC section 9). `found` repeats the operation in LM syntax.
2. Frames: the interpreter keeps a frame stack (fn calls, lambda applications, prelude fns applied as callbacks by prims) that is popped only on normal return, so it describes the fault after the exception; `try` truncates it when it catches a failure. Up to 3 names, innermost first; when the nearest user (non-stdlib) frame is deeper, it replaces the third name. `path`/`line` point at the innermost call site with a location (which can be in the stdlib, e.g. `list/sum/body/1` for a `list.sum` overflow); `user_path` is the call site in the nearest user frame.
3. Replay: the innermost user frame's call with the arguments it received (the outermost fn frame when every frame is stdlib), as `python3 -m lm run MOD.FN ARG.. [--allow E]..` (the fn's own effects). Values print as LM constants; own-module variants and records print unqualified, those of `use`d modules qualified; function values or values of modules the frame's module does not use make it `unavailable (<reason>)`, as does a command over 400 characters. Known limit: `lm run` resolves MOD on its default search path, so a replay of a module elsewhere (e.g. a fixture under tests/) needs that path loadable.
4. Exit codes, kept minimal for the parallel `lm run` work (ADR-031 item 3): `lm run` prints runtime faults (E-OVERFLOW, E-RECURSION-LIMIT, E-REQUIRES/ENSURES-VIOLATED) on stderr and exits 70. E-EFFECT-DENIED is not in ADR-031's fault list and stays on stdout with exit 1; the printing of uncaught LM failures is left to the I/O branch.
5. The check-time literal rule covers every Int literal the checker sees, including `match` patterns. Bounds are pinned by `tests/spec/run/overflow-*.lm` (add, sub, neg via `math.abs`, mul, div, intermediate, `list.sum`, `list.fold` with `*`, a lambda under `list.map`) and the `int-*` cases of `semantics.lm`; `math.int-min`/`math.int-max` are zero-argument functions with examples.
