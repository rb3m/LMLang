# ADR-083 Backlog 30: device I/O as an OS-agnostic interface over per-OS adapters (2026-11-25, agent consensus)

Status: accepted (2026-11-25). Owner direction: "create an interface that's OS agnostic and then another layer that does the communication with the OS ... allowing that sort of work on any machine LMLang runs", delivered as an extension, not by growing core `fs`; test first on the owner's Mac (keyboard and mouse), then Linux.

Context: LM cannot express a device bridge. hotas-split (HID reports, grab, virtual joystick) and tartarus-bridge (grab a keypad, four virtual joysticks, LED feature reports, 80 ms timed pulses) are Python on Linux (Vault, `Intelligence/Gaming/`). LM runs on Linux and macOS; three runtimes must agree; stdlib only; Go builds are static with CGO_ENABLED=0. Function values are pure; self tail calls are loops, so a program can own its event loop.

Options considered: interface level (raw char device/ioctl, raw HID, SDL-style gamepad); macOS from Go ((a) cgo only for darwin builds that use the extension, (b) purego-style trampolines, (c) Go unsupported and Python via ctypes, (d) a helper process); packaging (core stdlib, first-party opt-in `ext/`, separately versioned native plug-ins); one effect or several.

Decision (Claude, Codex, agy unless noted):
1. Two layers. Layer A is LM modules with one meaning on every OS. Layer B is one adapter per OS per runtime behind a fixed prim contract; a fake adapter backs examples. One conformance vector suite runs against every adapter and runtime. Adding an OS means adding an adapter, not changing Layer A. Layer A stays provisional until both the macOS and Linux adapters pass the suite.
2. Interface level: raw HID for physical devices plus declarative virtual input, as sibling modules. Raw ioctl leaks Linux structs and has no parity or fake world; an SDL-style abstraction loses vendor words and feature reports. Decoding (keyboard reports, vendor words, calibration) stays in LM as pure, example-tested code.
   - `bytes` (core, pure): built-in immutable `Bytes`; size, at, slice, concat, from-list/to-list (0..255), LE/BE get/put for u8 u16 s16 u32 s32, hex. Literal `(bytesof "0aff")` (hex pairs) prints the same way, so examples, scenarios and printed values round-trip. Also usable later for binary files and HTTP.
   - `hid` (ext): `enumerate -> (List hid.Info)` (vendor, product, usage-page, usage, interface, product name, serial, opaque id); `open id -> hid.Dev`; `read d -> hid.Report` (`report-id Int`, `data Bytes`; the adapter owns framing, so Linux's unnumbered-report 0x00 prefix never reaches LM); `write`; `feature-get d id len`; `feature-set`; `grab d Bool` (the OS and other apps stop receiving the device's input; Linux grabs every sibling evdev node as a group with rollback); `wait (List hid.Dev) timeout-ms -> (List Int)` (ready indices in argument order; also the timer); `close`; `supports CAP -> Bool`. Errors `hid.HidError (id Str) (msg Str)` with categories `not-found permission busy disconnected unsupported invalid-request io`. Handles are opaque (no equality, printing or external constants, like `pat.Pat`), invalid after unplug, closed by the runtime at exit with grabs released.
   - `vinput` (ext): `create spec -> vinput.Dev` from a record (name, vendor, product, axes with ranges, buttons, hats); `axis`, `button`, `hat`, `sync`, `close`. On exit or fault the runtime destroys the device, so no button stays pressed.
3. Effects by authority (Claude, Codex; agy preferred one `dev.io`): `hid.io` for reports and features, `hid.grab` for suppressing physical input, `vinput.emit` for injecting input. A monitor needs only `hid.io`; injecting input into the desktop is the most powerful and gets its own `--allow`.
4. Packaging: first-party modules under `ext/`, versioned with the toolchain, available only when a project opts in, so prim signatures, adapters and vectors move together. No third-party native code; that would be a separate owner security decision.
5. macOS (Claude, agy; Codex preferred (d), a first-party helper process shared by all runtimes): Python runtimes call IOKit's HID Manager through `ctypes`; Go uses cgo only when the program reaches `ext/` hid on darwin, so every other build stays static with CGO_ENABLED=0. Cross-building such a program for darwin from another OS is a build error, not a stub. `wait` runs the HID Manager's run loop until a report is queued or the deadline passes. Open with seize is `grab`. `vinput` is `unsupported` on macOS: virtual HID needs a signed DriverKit extension and entitlement. Reading keyboards needs the user's Input Monitoring permission (`permission` until granted); mice and joysticks do not.
6. Fake world and tests: `(given (hid ...))` declares a device catalog and scripted reports with virtual delays; checks assert writes, features, grabs and vinput frames at `sync`. `hid.wait` advances the same frozen monotonic clock as `time.mono-ms`, so timed-pulse loops run hermetically. Conformance vectors (JSON) cover numbered and unnumbered reports, two identical devices, unplug during a pulse, and sustained input across a release deadline.
6a. Replay (added by Claude while scoping P2): when `LM_HID_REPLAY` names a JSON trace (device catalog plus timed reports and unplugs), every runtime uses a replay adapter instead of the OS one and logs writes, features and grabs to `LM_HID_REPLAY_LOG`. The fake world uses the same trace model. This runs the conformance suite in all three runtimes and checks ported programs against recorded reports. Opt-in uses the existing project file: `(ext hid)` entries in `lm.deps`.
7. Delivery: (P1) core `bytes`; (P2) `ext/` opt-in, `hid`, fake adapter, conformance suite and the macOS adapter, tested on the owner's Mac with a keyboard and mouse; (P3) Linux adapter and `vinput` over uinput, hotas-split and tartarus-bridge ported and compared on recorded reports; (P4) revisit macOS `vinput` and other device classes (serial ports) when a program needs them.

Revisit when: a third OS is targeted, a program needs another device class, or the macOS cgo build proves too costly (then Codex's helper process).

Implemented so far (2026-11-25, v0.14.0): P1 and P2 by Codex (gpt-6.2-sol, medium), verified by Claude. Live on the owner's Mac: interpreter, Python and Go builds list identical devices; 7,699 trackball reports via Go with the report-ID byte stripped; Keychron keyboard reports via the Python target with key rollover; grab froze the pointer (owner confirmed) while 5,220 reports kept arriving, then released cleanly. Not yet live: unplug, feature reports, Input Monitoring prompt. Found while testing: long-running programs lost buffered output and cleanup on SIGTERM; every runtime now flushes, closes devices and exits 128+signal.

P3 (2026-11-27, owner's Linux workstation): P3a Linux hid adapter (sysfs, hidraw, EVIOCGRAB on sibling evdev nodes; Go stays static, CGO_ENABLED=0), P3b `vinput` over uinput (closed axis-name set x y z rx ry rz throttle rudder wheel gas brake; buttons map to BTN_TRIGGER then BTN_TRIGGER_HAPPY; `sync` emits changes only; replay logs vinput-create/frame/close), and hotas-split ported to `src/hotas-split`, all by Codex (gpt-6.2-sol, medium), verified by Claude. Live: identical device lists, 3,123 HOTAS reports byte-identical to a raw hidraw reader in all three runtimes, feature 0xF2 read, grab verified by EBUSY from another process and released on close and SIGTERM, unplug reported `disconnected` in all three runtimes, a uinput joystick round trip in all three runtimes with a js node and removal on SIGTERM. The port matches the Python bridge frame for frame on synthetic traces and on the owner's recorded session. Layer A (hid, vinput) has now passed the suite on both macOS and Linux adapters. Left in P3: port tartarus-bridge (it reads evdev key events today, so the port must decode the keypad's HID keyboard reports in LM), and switch the owner's services to the LM builds when the owner decides.
