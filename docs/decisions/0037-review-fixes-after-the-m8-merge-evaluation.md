# ADR-037 Review fixes after the M8 merge: evaluation order, no function equality, subject-first stdlib (2026-10-16)

Decided by Claude+agy consensus, Codex review (read-only reviews of the merged `m8` branch).
1. Bug (Codex): the Go backend printed `<=` and `>` as `less(right, left)`, so operands ran right to left. Comparison operands are now evaluated into temporaries in source order first (`tests/spec/build/cmp-order.lm`: the left operand prints, the right one fails).
2. Function equality (Codex): the interpreter compared function values by object identity and Go by pointer, and they disagreed on `(= + +)`. Instead of defining function identity in every backend, the checker rejects `=`/`!=` whose operand type contains `Fn` (directly, inside List/Opt, or in a record/sum field), including `=` passed as a value, with E-TYPE (`tests/spec/check/eq-fn.lm`). The check runs once a function's types are solved. Known hole: a rigid type variable (`a` inside a generic function, `list.index-of` on functions) is not checked.
3. Stdlib API (agy), subject first everywhere: `(str.split s sep)` and `(str.join parts sep)`; `list.append` is renamed `list.concat` (matches `str.concat`); `str.to-int` returns `(Opt Int)`: `None` for malformed or out-of-range text, never a failure or a fault, and `str.ParseError` is removed. This amends ADR-030 item 3 and ADR-034 (external input still never faults). SPEC section 7 now says `str.length` (ADR-017: prelude `len` is lists only). `fs.IoError`/`io.IoError` stay as they are. All callers, fixtures and the index golden were updated; `lm bench` re-run: S5 unchanged at 1.34x (still OPEN, ADR-025), S1 median 4.3% -> 4.4%.
4. Go backend follow-ups from the merge: the 14 M8(a) prims are implemented in `lm/runtime/go/prims.go` with ADR-034 semantics (`io.args` = `os.Args[1:]`; reads flush stdout first; `eprint` flushes stdout before writing stderr; host error texts differ from Python's, which ADR-034 allows). Lowering handles `(do ..)` and the list patterns `(list ..)`/`(cons h t)`. The Go E-OVERFLOW diagnostic now has the interpreter's shape (message, `data` with op, operands, bounds, frames, frames_omitted, user_path, replay): frames come from the Go call stack at the fault (lambdas are lifted to named Go functions `L<n>_<owner>` so they can be named `(lam) in mod.fn`), the nearest user frame is kept visible, and replay is `unavailable (compiled binary)`. Difference: for overflow inside a prim callback (`(list.fold xs 1 *)`) the `path` names the user function's body, not the exact call node, because call sites are not tracked at run time.
5. Stdout buffering: ADR-034 makes `io.print` flush every line in the interpreter; binaries keep ADR-036 item 3 (line-buffered on a terminal, block-buffered to a pipe or file, flushed before reads, before stderr writes, before a failure or fault, and at exit). Output order as seen by a reader of both streams is the same in both.
Built-binary fixtures now cover `io.args`, stdin (`read-line`), `fs.read`/`write`/`exists` and a caught `fs.IoError`, `str.to-int` returning `None`, `do` and list patterns, and the overflow fixtures run under the interpreter too. The differential test also loads `tests/spec/build`.
