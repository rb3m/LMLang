# ADR-061 Optional exports, proven-safe division/indexing, inferred lambda types (S5 levers; 2026-10-18, agent consensus)

Context: S5 (median LM/Python token ratio, 13 bench tasks) is 1.34 against 1.3. Analysis (agy, re-measured by Claude): module headers, spurious `fails`, typed lambdas and loose bench programs are avoidable cost; exports alone move the median to 1.295. Owner rule (2026-10-18): LM is for AI only; fewer tokens beat human readability. Purposes stay required (Claude): they power `lm index` navigation (S1) and the Python baseline counts docstrings, so dropping them would move the goalposts.

Decisions:
A. Optional exports. A module without `(export ..)` exports every top-level fn, type (with variants), error and const; `(export)` with no names exports nothing; a non-empty list behaves as today. The example requirement follows real use: a pure fn needs at least one example if it is listed in `(export ..)`, or, in a module without an export clause, referenced from another module. Effectful fns still cannot have examples. The stdlib keeps explicit lists.
B. Proven-safe division and indexing. Facts: the conjuncts of every `requires` clause (pooled across repeated clauses), `if` conditions (the then-branch gets the condition, the else-branch its negation; nothing leaks past the `if`), and the left operands of `and` for the right operand. A fact compares an Int term (a parameter, a let-bound name, or `(len NAME)`) with an Int literal using `> >= < <= = !=` in either order, `not` flipping it; comparisons are normalized (e.g. `>= 1` is `> 0`, `> 0` implies `!= 0`) without overflowing Int bounds. Facts refer to binding identities; a function's own `requires` is not assumed while checking that `requires`. Uses: `/` and `mod` whose divisor term is proven nonzero do not fail DivZero; `(list.nth xs k)` with Int literal `k >= 0` and a proof of `(len xs) > k` does not fail OutOfRange. Every discharged site keeps a runtime check: if its condition is ever false (possible only with `--no-contracts` and a violated precondition), it is an uncatchable fault, never an undeclared failure, in both backends. A now-unneeded `(fails ..)` is the existing unused-fails warning.
C. Inferred lambda parameter types: `(lam (a b) body)`; all parameters typed or all untyped per lambda. Types are solved by unification with every contextual constraint before the existing default-to-Int rule; rigid signature generics are preserved; anything still unresolved outside that rule is an error.
D. (Not a language change) The bench LM programs are rewritten to the tersest idiomatic LM with current features, behaviour unchanged. S5 stays provisional until the real-tokenizer re-measure (ADR-025, ADR-052).

Who agreed: Claude proposed A-C and D; agy agreed on A and C and amended B (pool repeated requires, normalize inequalities); Codex (gpt-6.1-sol) agreed on A and C and amended B (binding identities, no self-assumption, no leaks past joins, a runtime fault at every discharged site instead of a `--no-contracts`-only rule) and A (`(export)` stays meaningful). Both flagged the example-requirement problem in A, resolved by the cross-module-use rule. Owner not consulted, per the 2026-10-18 instruction to settle design by agent consensus.
