# ADR-024 M6 gate decision: ADJUST, then re-gate (2026-10-15)

Measured on 13 tasks (LM and Python, equivalence-checked on shared cases), 43 injected "plausible but wrong" edits, the combined 40-function project, and the approved scenarios (full table: bench/results/summary.md, regenerate with `lm bench`):
- S1 3.6% median vs project text (target <= 25%) but only because the 13 modules are independent; against the module file alone it is 47% median and 110% max (slices include stdlib signatures). S1 is met on paper and NOT demonstrated for real large projects.
- S2 8.9% median (target <= 30%); max 71% for tiny files. Baseline is regenerating the whole file; a Python agent using str-replace edits pays about the size of old+new text, so the true advantage is the structured addressing and automatic re-check, not raw size.
- S3 43/43 = 100% (target >= 90%). Caveat: I wrote the injected errors, so this measures the checker against my model of hallucinations, not against real model errors. Logic bugs (3 injected) are invisible to `check` and caught by `test`, as expected.
- S4 13/13 within two iterations (target >= 80%); first try 10/13. All three first-try failures were the same mistake (calling `list.` without `(use list)`), repaired mechanically by the diagnostic's `fix` op. Caveat: I am both author and subject, so this is a lower bound on difficulty for other agents.
- S5 **1.37x** vs Python with docstrings, example asserts and contract asserts (target <= 1.3x); 1.41x with punctuation runs merged (sensitivity); 3.2x vs bare Python. MISSED. Median hides a spread: perimeter 0.87x, bank 1.12x, grades 1.19x, but roman 2.34x, dot 2.05x, greet 2.64x.
- S6 6/6 approved scenarios pass, guard OK.
- Harness finding: the equivalence run exposed a wrong description I wrote (mean "rounded toward zero" while LM `/` floors). `check` and `test` could not see it because the examples used positive numbers. Lesson: examples are only as good as their inputs; acceptance scenarios and cross-implementation cases catch what contracts do not.

Decision. ADR-011 names S5 as a fallback trigger, and S5 missed. The miss is 5% and concentrated in tasks where the stdlib forces index recursion with `fails OutOfRange` boilerplate (no head/tail/zip, no sequencing form), which is fixable without touching the core design; the ceremony that costs tokens is also what produced S3 = 100% and S4 = 100%. So: do not fall back yet, and do not expand LM either. M7 is a bounded repair (ROADMAP) measured on the same tasks and mutations. Pre-registered rule: if M7 does not bring S5 to <= 1.3x without regressing S3/S4/S6, execute the ADR-011 fallback (strict subset + toolchain over typed Python), reusing index/slice/edit/diagnostics/accept. Not changed: the targets, the tasks, the mutation list (no moving goalposts); new tasks may be added but results for the original 13 are reported separately.
Open question the benchmark cannot answer: whether slices pay off on large projects. A realistic test needs a >= 5,000-token multi-module project written by someone else; list it as a risk, not a result.
