# ADR-043 Float implemented (M9): choices ADR-039 left open (2026-10-16)

Implements ADR-039 in every layer (reader, printer, checker, interpreter, stdlib `float`, `str.from-float`/`str.to-float`, lowering, Go backend and runtime). No item of ADR-039 was changed; these are the decisions it left open, made by Claude under ADR-030's delegation.
1. Operator typing: `+ - * /` and `< <= > >=` have type `n n -> n` / `n n -> Bool` with one constrained type variable; the constraint (Int/Float, or Int/Float/Str) is checked with the ADR-037 equality check once a function's types are solved. An operand type nothing determines defaults to Int (as before). A rigid type variable fails the constraint (E-TYPE), unlike ADR-037's equality hole.
2. DivZero: decided where the `/` appears. If either operand is already known to be Float it is Float `/` (never DivZero); otherwise it counts as Int `/`. A `/` whose operands become Float only later in inference would ask for a spurious `(fails DivZero)`; not seen in practice. Revisit if it is.
3. `float.floor ceil round trunc` all return Int (the ADR lists them together); a Float-to-Float rounding was not needed. Out of range is E-OVERFLOW with `op` = the function name and the one Float operand. `round` is exact (Python: `trunc` plus the exact remainder; Go: `math.Round`), never `floor(x + 0.5)`.
4. `str.to-float` grammar (ADR-039 item 5 said "the literal grammar plus surrounding-whitespace-free decimal forms"): `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?`, so `1.`, `.5`, `+2` and integer text parse; whitespace, `_`, hex, `inf` and `nan` do not. Text that rounds to an infinity is `None`; underflow gives `Some 0.0` or a subnormal. Python and Go apply the same regex before their (correctly rounded) parsers.
5. E-FLOAT diagnostics: lead "Float result not finite", `bounds` = +-1.7976931348623157e+308, guidance "...; a non-finite Float cannot be caught." The Go runtime prints `data.operands` and `bounds` with Go's JSON number format (`1` for `1.0`); only `code` and the message's LM text are compared across backends.
6. A literal that is not finite keeps its source text in the AST (`Atom.raw`), so `lm fmt` never turns `1e400` into `inf`; finite literals are canonicalized (`1.50` -> `1.5`, `-0.0` -> `0.0`, `1e-400` -> `0.0`). Go code embeds literals as exact bit patterns (`fbits(0x..)`), not decimal text.
7. Tests: `tests/unit/test_float.py` compiles a harness against the Go runtime and compares canonical text (40,000 values: random bit patterns and short decimals, both signs), `str.to-float` (6,000 texts) and `+ - * /` (12,000 pairs) with the interpreter. `tests/spec/build/bin-float.lm` pins the absence of FMA (`0.1*10.0 - 1.0` must be `0.0`). `go build` now passes `-buildvcs=false` (a stray VCS directory above the temporary build directory made builds fail intermittently).
