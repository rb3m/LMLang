# ADR-062 `lm build --target py`: a self-contained Python backend over the IR (backlog 8; 2026-10-18, agent consensus)

Context: backlog 8 (ADR-027) plans a Python server backend: DreamHost shared hosting is Linux x86_64 with Python 3.12, and whether Go binaries may run there was never tested. `lm build` also needs a Go toolchain on the build machine. The interpreter already runs anywhere, but it is a tree-walker and needs the whole repo.

Decisions:
1. `lm build --target py MOD.FN [-o FILE]` emits one self-contained Python file (stdlib only, Python >= 3.10), default name `<fn>.py`, starting with `#!/usr/bin/env python3` and written executable. It is generated from the same IR as the Go backend (no second lowering); no Go is needed. Go stays the default target; Go-only flags (`--os`, `--arch`) are rejected with `--target py`.
2. Semantics are those of the interpreter oracle and Go binaries: Int64 overflow checks (E-OVERFLOW), Float rules (-0.0 normalized, E-FLOAT, exact Float literals, canonical printing), the pinned float math, the AVL Map/Set, SplitMix64 `rand` with `LM_SEED` (validated at startup), JSON, UTF-8 I/O, the same JSON diagnostics, exit codes (0/1/3/70) and flushing, argument handling per ADR-031 (`io.args`, `--` passthrough), exactly the entry's declared effects granted, contracts unless `--no-contracts`, E-PROOF-VIOLATED at discharged sites. Equality is LM's type-strict structural equality (Python's `True == 1 == 1.0` must not leak). Failures and faults stay distinct, evaluation is left to right, tail loops keep fresh closure captures, simultaneous parameter replacement and innermost-first postconditions.
3. Runtime code is embedded mechanically from the `lm/` runtime sources at build time (never maintained as copies), and only the parts the program reaches (e.g. float math only if a float math prim is used, the AVL tree only for Map/Set).
4. Recursion: self tail calls are loops; other calls use explicit LM call-depth accounting with a pinned, documented Python-target limit (like Go's own limit, ADR-031), run in a thread with a conservative stack so shared-host memory caps do not break startup; beyond the limit is E-RECURSION-LIMIT, never a Python crash.
5. Tests: the differential corpus and the build spec fixtures run on the Python target wherever python3 exists (no skip), three-way with Go where Go exists; the emitted file is executed from a directory outside the repository to catch hidden imports.
6. Out of scope: `lm serve`, HTTP hosting (a separate deployment smoke test on the real host), content-addressed store, effect mocking, PHP.

Who agreed: Claude proposed 1-6; agy agreed on 1, 2, 4, 5 and amended 3 (embed only reachable runtime, conservative stack, shebang, argv parity); Codex (gpt-6.1-sol) agreed on 1, 4, 5 and amended 2 (declared effects only, mechanical embedding) and 3 (explicit depth accounting with a tested limit), and listed the equality, closure, failure/fault, outside-repo and Go-only-flag requirements, all adopted.
