# ADR-075 Backlog 19: text patterns, module `pat` (2026-10-19, agent consensus)

Context: text processing needs reusable patterns with captures and predictable search cost. Delegating matching to Python `re` or Go `regexp` would give different supported syntax, priorities, captures and error messages across targets.

Decision:
1. Implement our own Pike VM in every runtime, stepping on Unicode scalars. An ordered thread list deduplicates by program counter (first wins), copies captures on split and guards empty iterations of nullable loops. A single-pass unanchored search uses an implicit lazy prefix and leftmost-first (Perl-style) priority. Repetition bounds are at most 1000, the expanded program at most 10000 instructions, group nesting at most 100.
2. One search is O(program size × text length). Find-all, split and replacement repeat searches, so pathological patterns can be quadratic in text length over the full iteration, as with RE2/Go. There is no whole-text linear guarantee.
3. Grammar: literals, dot except LF, classes with code-point ranges (first `]`, first/last `-` literal), ASCII `\d`/`\w`, `\s` U+0009..U+000D and U+0020, their negations, `\n \t \\` and escaped metacharacters, absolute `^`/`$`, capturing and `(?: )` groups, alternation, `* + ? {n} {n,} {n,m}` and lazy variants. Empty groups/alternatives are allowed. Unknown escapes, empty classes, reversed ranges, dangling quantifiers and unbalanced parentheses fail. Word boundaries, backreferences, lookaround, named groups, flags and Unicode classes are unsupported.
4. `pat.compile(source Str) -> Pat` fails `pat.BadPattern (pos Int) (reason Str)`, with a zero-based scalar position and fixed reason shared across targets. Literal compile sites are validated at check time: invalid literals produce E-PATTERN with the same position/reason, valid literals discharge BadPattern using ADR-061 proof sites and retain the runtime E-PROOF-VIOLATED guard. Ordinary Str literals are unchanged.
5. Subject-first API: `matches` enforces the entire text during matching, `find -> (Opt Match)`, `find-all`, `split`, `replace-all` (literal replacement) and `replace-with` (pure, total `(Fn (Match) Str)`). Match fields: start/end scalar offsets (end exclusive), text (group 0), groups (`(List (Opt Str))`, 1..N in opening-parenthesis order). Nonparticipants are None; repeated captures retain their last iteration, including a final empty iteration. After an empty match resume one scalar later; emit a terminal empty match once. Split preserves empty fields and inserts no captures. No Unicode normalization is performed.
6. Pat is opaque: no equality, ordering, Map/Set keys or external constants, transitively through containers and user types. It prints `<pat>`.

The example requirement follows representability: signatures containing Pat do not require examples, since opaque arguments/results cannot be expressed as example constants. Explicit examples still reject Pat values. Concrete caller wrappers and the shared conformance vectors exercise these operations.

Live consuming/match threads deduplicate strictly by pc. Epsilon closure also distinguishes the count of enclosing repetitions entered at the current position, bounded by the nesting cap; this allows a final empty iteration to update captures without revisiting arbitrarily many paths. Empty optional iterations exit the repetition, while mandatory iterations still run to their lower bound.

Fixed reason contract: `unknown escape`, `trailing escape`, `unclosed class`, `empty class`, `reversed range`, `invalid range`, `unclosed group`, `unexpected parenthesis`, `unsupported group`, `dangling quantifier`, `invalid repetition`, `repetition bound`, `program limit`, `nesting limit`. Escape errors point at the backslash; class errors at `[`, range errors at `-`; group errors at `(` except an unexpected `)` at itself; quantifier errors at the quantifier, repetition errors at `{`; nesting errors at the 101st opening parenthesis; program limit at 0.

Who agreed: agy and Codex (gpt-6.1-sol) agreed in two rounds. agy contributed the BadPattern failure over Opt, scalar stepping, pinned messages, capture rules and lazy bounded repeats, and proposed `pat.test`, replaced by the literal-discharge rule 4 that both accepted. Codex contributed the VM pinning, instruction and nesting caps, the grammar edge rules, literal-only check sites, separate literal and callback replacement, the empty-match rules, and the objection that led to the narrowed bound in rule 2 (it offered narrowing as an acceptable resolution).

Verification: shared JSON conformance vectors are run by the interpreter, standalone Python and native Go; checker fixtures pin literal validation, dynamic failure declarations and opaque-type restrictions. A bounded-process timing test searches `(a*)*b` against 5000 `a` scalars to detect backtracking.

Claude's verification: Claude ran the full gate (297 unit tests including HTTP loopback, check, test, accept --guard, the three bench projects, export scan) and a probe covering captures, last-iteration groups, empty-match find-all and replace, split with empty fields, astral scalars, callback replacement and BadPattern positions; interpreter, Go and Python output was byte-identical. `(a*)*b` matched 5,000 and 20,000 `a`s in under 0.2 s in the interpreter, where Python's backtracking `re` needs 1.1 s for 25. Implementation by Codex (gpt-6.1-sol, high effort), resumed once after a usage limit.
