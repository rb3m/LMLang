# ADR-022 Edits are AST operations addressed by node paths; rename uses the reference graph (M4)

Ops rebuild immutable trees at paths (`locate`/`set_at`), pass the result through `canonicalize` (validation + canonical order), and reprint. `rename` rewrites exactly the atoms the checker recorded in `prog.refs` for the symbol (no textual search), then re-checks and rolls back if any new error appears. Diagnostics' `fix` objects are executable via `edit apply`, closing the generate-check-fix loop. Why: output cost proportional to the change (S2), refactors without grep, no stale-text hazards. Found and fixed while testing rename: the resolver computed a module's exports after other modules had already resolved signatures against it (false E-NOT-EXPORTED for types used in signatures across modules); exports now resolve in their own pass before any type/signature resolution (fixture `tests/spec/check/multi-types`).
