# ADR-049 M11: built-in `Map` and `Set` (2026-10-17, agent consensus)

Process (ADR-030): Claude proposed; agy and Codex agreed and refined; tie-breaks favour one way to write each thing (G8). Evidence: `colsum.add-to` and the outside author's ledger group by linear scan (ADR-038, ADR-044).
1. Types `(Map k v)` and `(Set a)`, built in (user types still cannot take parameters). Keys and elements must be Int, Str, Bool or Float, checked after unification like the ADR-039 numeric constraints (E-TYPE otherwise). Values are immutable; `=` is structural and independent of tree shape or insertion history.
2. Order: every traversal (printing, `keys`, `values`, `fold`, `to-list`) is in ascending key order: Int and Float numerically (Float `-0.0` cannot exist, ADR-039), Str by Unicode code point (UTF-8 byte order agrees, so Go needs no special comparison), `false < true`. So results never depend on insertion order or backend.
3. Representation: a persistent balanced search tree with O(log n) `put`/`get`/`remove`, the same algorithm in the interpreter and the Go runtime (performance only; semantics are fixed by item 2).
4. Literal forms (special forms, so names avoid the `map`/`set` modules): `(mapof (k1 v1) (k2 v2) ..)` and `(setof e1 e2 ..)`. Keys of `mapof` and elements of `setof` must be literal constants (Int, Str, Bool, Float literals); a duplicate is E-DUP-NAME at check time. `mapof` values are any expressions, evaluated left to right in source order. `(mapof)`/`(setof)` are the empty map/set; there is no `empty` function. The printer and `lm run` print maps and sets in these forms in key order, so printed values are valid example constants.
5. Module `map`: `put (m k v)` (replaces an existing binding), `get (m k) -> (Opt v)`, `has`, `remove` (absent key: unchanged), `size`, `keys -> (List k)`, `values -> (List v)`, `fold (m init (Fn (b k v) b))`, `update (m k default (Fn (v) v))` = store `f(existing value, or default when absent)`. Module `set`: `add`, `has`, `remove`, `size`, `to-list`, `from-list`, `fold (s init (Fn (b a) b))`, `union`, `intersect`, `diff`. Function values stay pure and total (ADR-015).
6. Migrate `examples/colsum.lm` to a `Map Str Int`: its output order changes from first-seen to key order, so its purpose and examples are revised explicitly (Codex). Measure tokens and runtime before/after in EVIDENCE.md.
7. Tests: backend agreement across insertion orders, deletions with rebalancing, empty-literal type inference, Float and Str key ordering, printing round-trips (printed value re-read as an example constant), and large maps (100k keys) in a build fixture.
