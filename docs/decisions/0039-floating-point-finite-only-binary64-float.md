# ADR-039 Floating point: finite-only binary64 `Float` (2026-10-16, agent consensus)

Process (ADR-030): Claude proposed, agy and Codex reviewed independently; all three agree on the core (finite-only values, uncatchable fault, explicit conversions, exact `=`). Owner priority: backlog item 1.
1. Type `Float` = IEEE-754 binary64; every operation rounds to binary64 nearest/ties-to-even; subnormals are kept and underflow to zero is allowed. No fused operations: backends must not let a compiler contract `x*y+z` (Go may on arm64; wrap each operation in an explicit `float64(..)`), and every intermediate result is checked.
2. Literals: `-?[0-9]+(\.[0-9]+)?([eE][+-]?[0-9]+)?` with at least a `.` or an exponent (`1.0`, `-0.5`, `2.5e-3`, `1e+16`). A literal that is not finite in binary64 (`1e400`) is the check-time error E-FLOAT. The printer writes the canonical text (item 6). Float literals are not allowed in `match` patterns (E-TYPE): use comparisons.
3. Operators: `+ - * /` accept Int Int or Float Float; `< <= > >=` accept Int, Float or Str pairs; `= !=` are exact. Mixing Int and Float is E-TYPE. The constraint is checked after unification, so `(list.fold xs 0.0 +)` works. `/` on Float never fails DivZero (dividing by zero is the fault below); `/` on Int keeps its DivZero rule. `/` and `mod` remain unusable as function values (agy; Codex preferred allowing Float `/` as a callback: rejected for one simple rule, a lambda does it). `mod` is Int only.
4. Non-finite policy: an operation whose result is NaN or +-Inf is the runtime fault E-FLOAT (exit 70, uncatchable, never declared, still checked under `--no-contracts`), with the E-OVERFLOW diagnostic shape (ADR-030 item 5). So every Float value is finite and `=` is total and reflexive. Negative zero is normalized to `0.0` on creation, so `-0.0` never exists and prints `0.0` everywhere.
5. Stdlib: new module `float`: `from-int` (nearest), `floor` `ceil` `round` (half away from zero) `trunc` (Float -> Int: apply the rounding, then check the mathematical integer against Int bounds; outside is E-OVERFLOW; never compare against `from-int(int-max)`, which rounds up), `sqrt` (negative is E-FLOAT), `abs` `min` `max` `sum`. In `str`: `from-float` and `to-float -> (Opt Float)`; `to-float` accepts the literal grammar plus surrounding-whitespace-free decimal forms, and returns None for malformed, overflowing, `inf`, `nan` text (external input never faults).
6. Canonical text (printer, `lm run`, `str.from-float`, binaries): Python's `repr(float)` exactly: shortest round-trip digits; positional when the decimal exponent is in [-4, 16), otherwise `d[.ddd]e+XX`/`e-XX` with at least two exponent digits; positional forms always contain `.` (`100.0`, `0.0001`, `1e-05`, `1e+16`, `1.5e+300`). The Go runtime implements this rule explicitly (strconv's `g` format differs, e.g. `100`).
7. Tests: spec fixtures and differential fixtures pin rounding, ties, subnormals, conversion bounds (2^63 boundaries), division by zero, non-finite faults, `-0.0` normalization, and canonical text; the differential test must also run on arm64 (the owner's Mac Mini) to catch fused operations.
Revisit: if an experiment needs decimal money arithmetic, add a fixed-point `Decimal` type rather than relaxing Float.
