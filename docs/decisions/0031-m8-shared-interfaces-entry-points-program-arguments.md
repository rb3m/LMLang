# ADR-031 M8 shared interfaces: entry points, program arguments, exit codes, effects in binaries (2026-10-16)

Context: M8 is built in parallel (I/O stdlib, 64-bit Int, Go backend), so the pieces must agree on how a program meets the operating system. Decided by Claude as M8 coordinator under ADR-030's delegation; agents may refine it with a later ADR, not silently.
1. Entry point. `lm build MOD.FN` accepts a function with no parameters returning `Unit` or `Int`. `Int` is the process exit status (0-255; anything else is a runtime fault E-EXIT-RANGE). `Unit` exits 0. Nothing is printed for the result.
2. Program arguments. `io.args` (sig `-> (List Str)`, eff `io.in`) returns the command-line arguments after the program name. Under `lm run MOD.FN [LM-ARGS..] [--allow ..] -- A B C`, the words after `--` are the program arguments; `lm run` keeps printing the result as before (it is a function runner, not the binary).
3. Outcomes, identical in `lm run` and binaries: success exits 0 (or the returned status); an uncaught LM failure prints `(fail Err args..)` on stderr and exits 1; a runtime fault (E-OVERFLOW, E-RECURSION-LIMIT, E-REQUIRES/ENSURES-VIOLATED, E-EXIT-RANGE) prints its one-line JSON diagnostic on stderr and exits 70 (EX_SOFTWARE), so callers can tell a program bug from a reported failure. [`lm run` changes from exit 1 to 70 for faults.]
4. Effects in binaries. Building grants exactly the entry function's declared `eff` set; the checker already proves nothing exceeds it, so binaries take no `--allow` flag (ROADMAP M8(d) said "--allow at binary start"; dropped as fuss with no safety gain, since the grant is visible in the entry signature). Binary arguments belong entirely to the program.
5. Contracts. On by default in binaries; `lm build --no-contracts` compiles them out. Overflow checks are never removed (ADR-030).
6. Stdin/stdout. Output is line-buffered UTF-8 text and flushed at exit and before any fault. Reading is UTF-8; invalid UTF-8 input is the I/O failure of the reading function, not a fault.
