# ADR-028 Slice signature blocks include `requires` and `ensures` (2026-10-16)

Context: an external review (AGYS_OPINION.md) found that `lm slice` printed callees as `purpose sig eff fails` only, so a caller's slice hid the callee's preconditions. That contradicts G1/G3 (contracts are part of the signature) and ADR-021's claim that nothing outside the slice changes what the root means: an agent cannot respect a `requires` it cannot see. The sufficiency test did not catch it because it tested the block as defined, not the contract.
Decision: a callee's signature block is `purpose sig eff fails requires ensures`; examples and body stay out. Types and errors mentioned in those contracts join the type closure. Functions called inside a callee's contract are not added (contracts are pure and total; slice them if needed). Tests: mutations of a callee's `requires`/`ensures` must change the slice, a callee `example` mutation must not, and a type reachable only through a callee contract is included (tests/unit/test_index.py).
Why examples stay out: they illustrate behavior rather than constrain callers, they are the largest clause, and `explain`/`--bodies` show them on demand.
Cost (re-run of `lm bench`): S1 median 3.6% -> 4.0% of project text; against the module file alone median 49.7% -> 52.8%, max 114.9% -> 122.3% (stdlib callees such as `list.map2` carry `requires`). S2-S6 unchanged. The re-run used Python 3.14 locally (the recorded run used 3.10): four `py_bare` counts moved by 2 tokens from differences in stripping Python source, with no change to the S5 headline (1.34x; 3.02x bare). Revisit: if contract text dominates slice size on real projects (then show contracts only for direct callees, never trim them under `--budget`).
