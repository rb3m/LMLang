# ADR-063 Pinned Unicode casing, code points, `\u{..}` escapes, pinned whitespace (backlog 3; 2026-10-18, agent consensus)

Context: backlog 3 deferred Unicode casing and a character type. Host casing differs (Python's `str.upper` uses full mapping, `ß` -> `SS`, `İ`.lower() has 2 code points, and its Unicode version follows the Python release; Go's `strings.ToUpper` maps per rune with Go's own version), but results must be identical in the interpreter, Go binaries and the Python target (ADR-062). Str literals only have `\" \\ \n \t`, so a string holding NUL or CR cannot be printed back as a literal. `str.trim`'s "Unicode whitespace" is already host-dependent (Go patches `unicode.IsSpace` to match Python's `isspace`).

Decisions:
1. `str.upper`, `str.lower`: Unicode simple case mapping (one scalar to one scalar; length never changes; `ß` stays `ß`; no locale rules; unmapped, unassigned and noncharacter scalars unchanged) from Unicode 16.0.0 `UnicodeData.txt`. A committed generator script builds a compact range/delta table from that file (its SHA-256 recorded in the generator), never from host casing functions; the same table is embedded in Python, Go and the Python target ("LM Unicode tables v1"); changing the version needs an ADR. A test compares every scalar's mapping across all targets. SPEC and CHEATSHEET state that simple casing is lossy: upper/lower are not inverses and not a case-insensitive comparison. `upper-ascii`/`lower-ascii` stay.
2. No Char type: a character is a one-scalar Str. `str.to-codes (s) -> (List Int)` returns Unicode scalar values; `str.from-codes (cs (List Int)) -> Str` builds a string, failing the new exported error `str.BadCode (code Int)` on the first value, left to right, that is negative, above 0x10FFFF or a surrogate (0xD800-0xDFFF), checked before any host string conversion; one allocation, not a fold.
3. Str literals gain `\u{H..}` (1-6 hex digits, a scalar value; anything else is a check-time error). The printer writes `\u{..}` for every control character other than `\n` and `\t` (including CR and NUL), so every Str value prints as a literal that reads back to the same value.
4. `str.trim` whitespace is pinned to the explicit set U+0009..U+000D, U+001C..U+0020, U+0085, U+00A0, U+1680, U+2000..U+200A, U+2028..U+2029, U+202F, U+205F, U+3000 (today's behaviour), in all targets.
5. Every Str is a sequence of Unicode scalar values at every boundary: file and stdin input already fail `io.IoError` on invalid UTF-8 and JSON rejects unpaired surrogates; program arguments that are not valid UTF-8 have each invalid byte sequence replaced by U+FFFD identically in all targets.
6. Out of scope: full/special casing, case folding, normalization, grapheme clusters, locale rules, character classes.

Who agreed: Claude proposed 1, 2 and 6; agy agreed on 1 and 3-of-the-original (scope) and amended 2 (`to-codes` naming) and raised table size, surrogate handling, caseless-comparison misuse, `from-codes` performance and generator provenance; Codex (gpt-6.1-sol) agreed on 1 and the scope, amended 2 (scalar values, first-invalid order) and raised the literal round-trip gap (item 3), the host-dependent `trim` (item 4), input boundaries (item 5), checksum pinning and exhaustive cross-target tests. All adopted.
